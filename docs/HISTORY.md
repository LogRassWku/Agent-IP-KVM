# Agent IP KVM 项目历史

本文档记录项目的重要决策、验证结果和方向变化。功能完成情况以对应需求的验收结果为准。

## 2026-09-06：PC 模型配置器首版

- 模型菜单为尚未配置的 PC Agent 增加独立“配置”入口；配置过程在一个专用会话中显示模型、安装目录、模型目录、阶段进度和事件记录。
- 根据已缓存的被控主机磁盘信息生成安装位置选项；当前推荐 RTX 4070 Laptop + 32 GB 内存使用具备视觉和工具能力的 `Qwen3.5 9B`，并保留 `Qwen3.5 4B` 轻量选项。
- 开发板保存有限状态的安装任务，通过一次性随机地址向被控 Windows 主机提供本地化 PowerShell 引导程序；配对令牌不返回浏览器，也不写入仓库。
- 安装程序调用 Ollama 官方 Windows 安装脚本，设置用户级模型目录，拉取并校验模型，并把各阶段状态经认证回传至开发板。
- 新增受限 ASCII HID 输入器；模型配置启动接口只用它打开 Windows 运行框并键入由服务端生成的固定引导地址，不接受浏览器提供的任意命令。

## 2026-09-06：Agent 安全闭环首版

- 增加按需 JPEG 截图接口；Agent 模式无需恢复连续 MJPEG 流即可临时取一帧，并在完成后释放采集源。
- 增加白名单结构化动作、风险分级和摘要绑定审批。只读观察可自动执行，键盘动作及 BIOS、安装、磁盘类任务等待用户批准。
- Web 对话显示审批卡；动作、批准、拒绝、结果和错误写入不含截图的 JSONL 审计日志，HID 动作后自动取得验证帧摘要。
- Web 服务安装时生成本机 PC Agent 配对令牌；主机清单与 PC Agent 建议上报经过 Bearer 认证，建议缓存不能直接绕过策略调用 HID。
- 模拟视频和模拟 HID 已完成计划、拒绝未批准动作、批准、执行、动作后观察、审计和错误认证的端到端测试。
- RDK X5 在连续流已释放的状态下成功按需取得一张 255 KB 的 1920×1080 HDMI JPEG；真实画面语义按预期返回 `unknown`，采集源在请求结束后保持空闲。
- 实机 Web 页面已验证只读任务自动完成和 BIOS 类任务停在“等待批准”卡片，未向真实 HID 发送按键。
- 浏览器重新加载后会把尚未执行的旧审批卡标为过期，避免服务重启后误把历史批准当成可执行计划。

## 2026-09-06：确定双 Agent 接入边界

## 2026-09-06：修正 USB Gadget 解绑操作

- 真实设备调试发现，向 configfs 的 `UDC` 文件写入零字节不会解绑控制器；Windows 会继续保留原有枚举状态，HID 端点最终因主机不读取而返回 `EAGAIN`。
- 部署、失败回滚、移除功能和离线恢复脚本改为向 `UDC` 写入空行，使 USB 控制器真正解绑后再重新绑定。
- 在 RDK X5 上验证修正后的解绑会令 `UDC` 内容清空，重新绑定后设备恢复到 `configured` 状态。
- 四个 USB Type-A 接口属于 Host 模式，不能作为连接被控电脑的 HID Device 端口；真实闭环必须使用 QuickLink USB Type-C 设备口。

## 2026-09-06：RDK X5 相对鼠标接口验证失败，恢复绝对指针

- 在仅保留键盘与相对鼠标两个 HID 接口时，RDK X5 的相对鼠标设备即使单次写入 20 像素位移也返回 `EAGAIN`；问题不属于网页坐标计算。
- RDK X5 运行配置恢复为 Boot Keyboard 加绝对指针双端点，网页恢复按实际视频内容区域映射到 0..32767 坐标。
- 相对鼠标适配器仍保留在开源代码中，供具有可用相对 HID 端点的其他开发板选择。
- 后续实测发现绝对指针端点也会短暂返回 `EAGAIN`。写入层现改为在限定时间内等待端点恢复，而不是立即销毁适配器；适配器重新打开时也不再发送默认中心坐标，避免画面中的鼠标在中心与真实位置之间闪现。

## 2026-09-05：Web 鼠标改为自动绝对位置映射

- 删除“开始控制／停止控制”和 Pointer Lock 交互。网页打开且 HID 可用时，会持续监听鼠标在实际视频内容中的位置；指针移出视频后暂停更新。
- 新增 6 字节 USB 绝对指针报告，并保留原有 Boot Keyboard 与相对鼠标。网页位置按当前视频宽高比、留黑和 50%–200% 缩放计算为 0..32767 坐标，点击前再次同步位置。
- Gadget 安装与恢复文件包同步加入 hid.pointer，旧版已存在的键盘和相对鼠标可以原地升级；失败时只移除本次新建的功能并恢复原 UDC。
- RDK X5 复合 Gadget 加入第三个 HID 后出现端点资源冲突：Windows 只轮询绝对指针，旧键盘与相对鼠标不再就绪。板端服务因此采用键盘 + 绝对指针双端点配置，相对鼠标保留为其他平台的可选能力。
- 新增绝对指针适配器、Web 控制器和 HTTP 接口测试。电脑端四十项自动测试全部通过；开发板部署和目标电脑真实位置闭环待完成。

## 2026-09-05：项目构想形成

### IP KVM 方向

- 确定以开发板、视频采集和 USB HID 组成软硬一体 IP KVM。
- 明确开发板自带 HDMI 接口是输出口，采集被控电脑画面需要独立的视频输入设备。
- 项目目标包含操作系统运行前的画面和控制能力，因此未来需要支持 BIOS／UEFI 和系统安装环境。

### 双 Agent 构想

- 提出板端 KVM Agent 与可选 PC Agent 协作的方案。
- KVM Agent 独立于被控电脑的操作系统，负责画面观察、权限检查、有限执行和结果验证。
- PC Agent 仅在用户选择安装后运行，负责读取经过授权的系统内部信息并提供建议。
- BIOS 修改、磁盘操作、系统安装和删除数据等高风险动作必须展示具体计划，并由用户明确批准。
- PC Agent 的断连停用和自清理必须基于安装清单，只能处理能够证明属于本项目的文件。

## 2026-09-05：首款 USB 采集卡验证

### 已确认

- RDK X5 能够识别采集卡的 USB 视频和音频接口。
- Linux `uvcvideo` 驱动能够自动加载，并创建设备节点。
- 设备声明支持 MJPEG、多种分辨率和最高 60 fps。

### 未通过

- 720p/30、1080p/30 和 1080p/60 均未取得可解码的有效帧。
- V4L2、FFmpeg 和 OpenCV 三条读取路径均收到空数据。
- 内核记录 UVC USB 协议错误 `-71`。
- 更换 RDK X5 USB Type-A 接口和 HDMI 线后现象不变。
- 被控笔记本没有检测到采集卡对应的外接显示器，HDMI 热插拔／EDID 握手可能没有建立。

### 结论

- 设备枚举成功不能作为视频链路成功的依据。
- 当前采集卡需要继续交叉测试或更换，不能作为第一版稳定硬件基线。
- 该问题不阻止平台无关的软件接口设计，但真实画面闭环仍是首版验收的必要条件。

## 2026-09-05：视频源软件基线建立

- 使用 Python 3.10 标准库建立平台无关的视频源接口，定义能力查询、打开、启动、取帧、停止、关闭和健康状态。

- 下一项软件工作是实现 Linux V4L2 视频源适配器；该适配器可以先完成设备发现和能力查询，真实取帧仍受当前采集硬件问题影响。

## 2026-09-05：V4L2 设备探测实现

- 加入 Linux V4L2 探测模块，通过 `v4l2-ctl` 查询 `/dev/video*` 节点，不启动视频流。
- 输出设备路径、名称、驱动、总线、视频采集支持状态，以及离散的像素格式、分辨率和帧率组合。
- 对非 Linux 平台、无设备、缺少 `v4l2-ctl` 和单节点查询失败提供结构化状态；单个坏节点不会隐藏其他节点。
- 七项自动测试全部通过，其中五项覆盖 V4L2 信息解析、格式解析、无设备状态、平台不支持状态和模拟设备发现。
- Windows 实测正确返回 `unsupported_platform`。
- RDK X5 实机确认 Linux 环境与 `/usr/bin/v4l2-ctl` 可用；采集设备未连接时，统一命令正确返回 `no_devices`，没有把无设备误报为程序故障。
- 接入已确认故障的采集卡后，统一命令发现两个节点：`/dev/video0` 正确归类为视频采集节点并列出 30 个 MJPEG 模式，`/dev/video1` 正确归类为元数据节点且不声明视频格式。
- 首次实机探测暴露了总体能力与单节点能力混淆的问题；解析逻辑改为优先使用 `Device Caps`，新增元数据节点测试后共八项测试通过。

## 2026-09-05：确定故障采集卡的替代测试路线

- 当前采集卡只用于设备枚举、驱动识别、节点分类和格式查询，不再用于证明真实画面链路。
- 软件取帧、状态管理和后续浏览器传输先使用模拟源，并计划加入视频文件源。
- V4L2 真实取帧验收将使用普通 USB 摄像头或其他已知正常的 UVC 设备；这一测试只要求产生真实非空帧，不要求输入来自 HDMI。
- RDK X5 已安装 FFmpeg，但没有 `v4l2loopback` 模块和对应内核构建目录。当前不安装 DKMS 模块，避免在定制内核上引入额外变量。
- NanoKVM PCIe 保留为 IP KVM 功能参考和未来网络视频源测试设备，不能直接替代 RDK X5 的 UVC 采集输入。

## 2026-09-05：确定双模式交互与板端模型基线

### 双模式交互

- 产品界面划分为 KVM 模式和 Agent 模式。
- KVM 模式向用户显示实时画面，并允许经过授权的浏览器会话使用键盘和鼠标。
- Agent 模式隐藏实时画面并停用用户的浏览器键鼠输入，用户只通过自然语言提交任务；板端 Agent 仍可在权限策略约束下观察画面和执行动作。
- Agent 模式采用按需截图、画面变化检测和动作后复核，不要求持续高帧率。等待稳定界面时可降到每秒 0.2 至 2 次观察，快速界面变化期间再临时提高采样频率。

### 板端模型实测

- RDK X5 实测为 8 核 Cortex-A55，系统可用内存约 6.9 GiB，安装前可用内存约 6.6 GiB，根文件系统剩余约 20 GiB。

- 模型文件大小为 1,117,320,736 字节，SHA-256 为 `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`。
- 在 Ubuntu 22.04 ARM64 上从 `llama.cpp v0.4.0` 源码构建 CPU 运行时；官方同期 ARM64 预编译包要求 `GLIBC_2.38` 和 `GLIBCXX_3.4.32`，与当前系统不兼容，因此没有采用。
- 首次只读测试能够按要求输出 `action`、`risk` 和 `requires_confirmation` JSON。实测提示处理约 9.7 tokens/s，生成约 3.9 tokens/s，包含模型冷启动的一次回答约 29.3 秒。
