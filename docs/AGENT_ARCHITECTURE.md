# Agent 接入边界与实施顺序

本文档记录 Agent 正式接入前的架构决定。它把“会思考的模型”和“能直接控制电脑的执行器”分开，避免模型输出直接变成不可审计的键盘、鼠标或 BIOS 操作。

## 1. 两个 Agent 的职责

| 组件 | 主要职责 | 可以做什么 | 不应独立决定什么 |
|---|---|---|---|
| PC Agent | 已启动操作系统内的理解、规划和系统信息查询 | 读取经授权的主机清单，分析日志，查询网络资料，生成步骤和风险说明 | 绕过板端策略发送 HID，直接改分区、固件或 BIOS |
| KVM Agent | 开发板上的可信执行与恢复控制器 | 读取按需截图，识别约定的 BIOS／UEFI 状态，执行受限 HID 动作，验证结果并在异常时停止 | 自行批准高风险动作，执行任意 Shell 或任意按键序列 |
| 策略与审批层 | 统一决定是否允许动作 | 绑定目标、证据、风险、批准和回滚信息；记录审计事件 | 把“进入 Agent 模式”当作高风险操作批准 |

PC Agent 可以提出“进入 BIOS 并修改某项”的计划，再把其中必须经过视频和 HID 的步骤交给 KVM Agent。KVM Agent 即使收到 PC Agent 的建议，也必须重新检查当前画面、目标身份和用户批准凭据。

## 2. Agent 如何看见画面

KVM 模式继续提供给用户的实时 MJPEG 画面。进入 Agent 模式后停止这条连续浏览器视频流，采集后端保留按需取一帧的能力：

1. 任务开始时取得一张基线截图；
2. 发送一个受限动作；
3. 等待界面稳定或超时，再取得一张截图；
4. 用画面变化、OCR 或固定界面识别结果验证动作；
5. 结果不符合预期就暂停并请求用户处理。

空闲时每秒约 0.2 至 2 次观察已经足够，快速变化阶段才短暂提高频率。因此板端不需要一直解码 30/60 fps 的视频。第一阶段可以使用传统图像差异和 OCR；需要语义理解时，再把经过用户同意的单张截图交给 PC Agent 或远程视觉模型。

## 3. Agent 如何使用 HID

模型只生成结构化动作，例如 `tap("f2")`、`chord(["ctrl", "alt", "delete"])`、`type("text")`、`pointer(0.5, 0.5)` 和 `wait(2)`。板端将这些动作映射到统一 HID 适配器，并执行以下检查：

- 当前模式必须是 Agent，控制租约必须属于当前用户；
- 动作必须在允许的键、鼠标按钮和坐标范围内；
- 每个动作有超时，结束时释放所有按键和鼠标按钮；
- 动作前后保存截图摘要和 HID 报告摘要；
- 屏幕变化与预期不符、设备断开或目标身份改变时立即停止。

这条链路也适用于 BIOS：小模型不需要自由发挥，只需在固定页面和有限动作模板中完成状态匹配。任何无法确定的画面都返回“未知”，不会通过猜按键继续执行。

## 4. 联网查询边界

联网查询由独立的网络工具完成，和 HID 执行器隔离。工具应保存查询来源、时间和摘要；网页内容只能作为参考证据，不能直接变成执行命令。上传截图、主机清单或日志前，界面显示数据内容、目的地和用途，并取得用户批准。没有网络或用户拒绝时，Agent 仍能使用本地缓存和离线规则完成只读诊断。

## 5. 用户审批分级

| 风险级别 | 示例 | 默认行为 |
|---|---|---|
| 只读 | 查看主机清单、读取 BIOS 页面、比较截图 | 可自动执行并记录 |
| 可逆低风险 | 打开设置、输入一段普通文本、切换显示模式 | 会话内首次请求时提示，可按会话授权 |
| 高风险 | 安装程序、重启、修改启动项、写分区、改变安全启动 | 每次动作前显示审批卡，批准后才执行 |
| 不可逆或恢复困难 | 刷写固件、清盘、修改 BIOS 核心安全设置 | 默认拒绝；需要用户明确批准、恢复介质和现场可见证据 |

审批卡至少显示：目标主机、拟执行动作、原因、所依据的截图或系统信息、预期结果、可能影响、回滚方法和批准有效期。批准应绑定动作计划和当前证据摘要，画面或目标改变后自动失效。

## 6. 正式接入前仍需完成的工作

1. 增加按需截图接口和状态稳定检测，验证 Agent 模式释放连续视频后的取帧路径。
2. 将 Web HID 接口收敛为结构化动作 API，补齐独占控制、紧急停止、超时和审计日志。
3. 给被控端信息探针和主机信息接口增加一次性配对凭据。当前实机采集已验证数据格式，但测试使用了同一局域网的临时中转；正式部署需要让被控主机直接可达开发板，或使用受认证的 PC Agent 中继。
4. 加入审批状态机和动作前后证据绑定，先用模拟画面和记事本完成离线测试，再接入 BIOS 测试页面。
5. 把模型运行器做成可替换适配器。RDK X5 先用已经验证的 Qwen2.5-1.5B-Instruct Q4_K_M 做意图解析和结构化计划；PC Agent 可选择更大的模型承担系统理解和联网检索。板端小模型不承担高风险批准，也不作为唯一视觉判断来源。
6. 建立资源预算：Agent 模式释放连续视频缓冲，按需截图后及时释放图像；模型上下文、并发会话和缓存大小都受上限约束。

## 7. 推荐的首个 Agent 闭环

先不执行 BIOS 写入。用已采集的 `data/controlled-host.json` 和固定的 Windows 桌面截图做一个离线闭环：用户提交任务 → Agent 生成结构化计划 → 页面显示风险与审批卡 → 模拟 HID 动作 → 取得新截图 → 显示验证结果。这个闭环通过后，再把同一套策略接到真实 HID，最后才增加 BIOS 页面识别和可恢复设置任务。
