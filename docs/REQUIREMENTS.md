# Agent IP KVM 需求文档

版本：1.3

状态：需求基线草案

更新日期：2026-09-05

## 1. 文档目的

本文档定义 Agent IP KVM 的可追踪需求和验收标准。项目计划负责说明推进顺序，本文档负责回答“系统必须做到什么”和“如何证明已经做到”。

## 2. 产品目标

Agent IP KVM 是一套可部署到多种 Linux 开发板的开源软硬一体方案。它通过独立于被控操作系统的视频和输入链路，让用户远程观察并受控操作电脑；在此基础上，板端 Agent 和可选 PC Agent 可以提供诊断、建议和经过授权的自动化操作。

## 3. 范围与优先级

| 优先级 | 含义 |
|---|---|
| P0 | 第一版必须满足，否则不能形成最小 KVM 闭环 |
| P1 | 第一版稳定后实现，构成智能与安全差异 |
| P2 | 后续扩展能力，不阻塞首版交付 |

需求状态使用：`待实现`、`进行中`、`受阻`、`已验收`。只有满足验收标准并保存证据后，才能标记为 `已验收`。

| 编号 | 优先级 | 需求 | 验收标准 | 状态 |
|---|---:|---|---|---|
| FR-001 | P0 | 系统能够发现可用的视频采集设备 | 列出设备标识、驱动、设备节点和能力；无设备时返回明确状态 | 进行中 |
| FR-002 | P0 | 系统能够从支持的设备取得真实画面 | 连续取得非空、可解码帧，并保存分辨率、格式和实测帧率 | 受阻 |
| FR-003 | P0 | 系统能够在局域网浏览器中显示实时画面 | 浏览器连续显示画面；断流时显示明确错误；顶部工具栏始终可见；设置入口能够查看当前设备和视频状态 | 进行中 |
| FR-004 | P0 | 系统能够模拟有限的 USB 键盘和鼠标 | 测试电脑可识别 HID；完成一个无破坏性输入；停止后所有按键和按钮释放 | 待实现 |
| FR-005 | P0 | 系统提供身份认证和单一控制者机制 | 未认证用户不能查看或控制；同一时刻只有一个控制会话能够发送输入 | 待实现 |
| FR-006 | P0 | 系统提供紧急停止 | 用户触发后立即停止新动作并释放全部按键和鼠标按钮 | 进行中 |
| FR-007 | P0 | 系统记录关键操作 | 连接、授权、动作、结果、错误和停止事件具有时间、来源和结果记录 | 待实现 |
| FR-008 | P1 | KVM Agent 区分 BIOS／UEFI、安装界面和已启动操作系统 | 在约定测试集中输出类别、置信度和证据；不确定时明确返回未知 | 待实现 |
| FR-009 | P1 | KVM Agent 对一个固定 BIOS 页面提供只读解释 | 能识别页面名称和约定字段，只输出建议，不发送按键 | 待实现 |
| FR-010 | P1 | 高风险操作执行前展示结构化计划 | 计划包含目标、动作、风险、预期结果和恢复方法；批准前不能执行 | 待实现 |
| FR-011 | P1 | 每个自动动作后重新验证状态 | 当前画面与预期不一致时停止，不连续猜测按键 | 待实现 |

| FR-013 | P1 | PC Agent 提供经过授权的系统内部信息 | 第一版只报告操作系统、启动方式、磁盘和设备状态，不执行管理命令 | 待实现 |
| FR-014 | P1 | 两个 Agent 能够交换建议和证据 | PC Agent 的建议与 KVM 画面证据同时展示；PC Agent 不能绕过板端权限策略控制 HID | 待实现 |
| FR-015 | P1 | PC Agent 支持断连租约 | KVM 持续离开超过用户设定时间后，凭据失效且服务先进入停用状态 | 待实现 |
| FR-016 | P1 | PC Agent 能够安全卸载自身 | 仅删除带所有权记录的项目文件；系统文件、用户文件和其他应用文件零变化 | 待实现 |
| FR-017 | P2 | 系统辅助安装操作系统镜像 | 校验镜像、确认目标磁盘并获得明确批准后，在专用测试盘完成受监督安装 | 待实现 |
| FR-018 | P2 | 系统支持受限 BIOS 配置任务 | 在一台约定测试机器上完成可恢复任务；保存前再次批准；异常画面立即停止 | 待实现 |
| FR-019 | P0 | 首版 Web 页面提供固定视频工具栏 | 工具栏固定在页面顶部，不依赖鼠标悬停；只显示已经实现的视频功能及设置入口；按钮具有文字提示和明确状态 | 已验收 |
| FR-020 | P0 | 设置面板显示视频设备信息 | 显示后端、设备名称、节点类型、驱动、总线、格式、分辨率、帧率、健康状态和最近错误；无设备时显示可理解的说明 | 已验收 |
| FR-021 | P1 | 系统提供 KVM 与 Agent 两种互斥模式 | KVM 模式显示画面并允许授权用户发送键鼠输入；Agent 模式隐藏画面、拒绝浏览器键鼠输入，只接受自然语言任务；切换模式时释放全部按键和鼠标按钮 | 待实现 |
| FR-022 | P1 | Agent 模式按任务需要观察画面 | 空闲时不持续高帧率采集；任务执行时通过按需截图、变化检测和动作后复核决定下一次观察；采样策略和最近观察时间可审计 | 待实现 |

### 4.1 首版 Web 界面边界

- 主区域以深色背景显示视频，保持原始宽高比，并在可用空间内完整适配。
- 顶部工具栏始终可见，只包含状态刷新、全屏和设置，不显示项目标题或品牌图标。
- 无画面时，视频区域只显示“小圆点 + No Signal”。视频源可用时圆点为绿色，不可用或服务断开时为红色；后台查询期间保持原有颜色。
- 设置按钮打开设备信息面板，不在首版承担系统配置、账号管理或 Agent 配置。
- 尚未实现的 HID、虚拟介质和 Agent 功能不放置可点击的占位按钮。
- 视频中断后立即显示断流状态，不继续展示旧画面使用户误认为画面仍在更新。
- 首次实现以模拟源和视频文件源验收；接入正常采集设备后复用同一页面。

### 4.2 KVM 与 Agent 模式边界

- 模式切换必须由用户明确触发，并在审计记录中保存切换时间和发起者。
- 进入 Agent 模式时，页面停止向用户展示实时画面，浏览器控制会话立即失去键盘和鼠标发送能力，并释放所有未释放的输入状态。
- Agent 模式仅显示自然语言任务、结构化计划、风险、确认请求、执行进度和结果。
- 板端 Agent 可以在后台取得完成任务所需的画面证据，但默认使用低频或事件驱动采集；快速变化阶段可以临时提高采样频率。
- Agent 的每个动作仍受权限策略约束。模式切换本身不能视为对高风险动作的批准。
- 返回 KVM 模式前必须停止当前自动动作，或进入能够证明输入已经全部释放的安全检查点。

## 5. 平台与硬件需求

| 编号 | 优先级 | 需求 | 验收标准 | 状态 |
|---|---:|---|---|---|
| HW-001 | P0 | 核心软件不绑定单一开发板 | 核心模块不硬编码 RDK X5 名称、设备节点或 BPU API | 待实现 |
| HW-002 | P0 | 视频输入通过统一适配接口接入 | 适配器至少提供发现、能力查询、启动、取帧、停止和健康状态 | 进行中 |

| HW-005 | P1 | CPU 路径能够独立运行 | 禁用硬件加速时，基本采集、状态管理和权限检查仍可运行 | 待实现 |
| HW-006 | P2 | 支持可选硬件加速后端 | 至少一个 BPU、GPU 或 NPU 后端通过适配接口运行，并有性能对比 | 待实现 |

## 6. 安全与隐私需求

| 编号 | 优先级 | 需求 | 验收标准 | 状态 |
|---|---:|---|---|---|
| SEC-001 | P0 | 默认仅允许本地或受信网络访问 | 新安装状态不向公网暴露管理界面 | 待实现 |
| SEC-002 | P0 | 不在仓库保存凭据和隐私画面 | 自动检查不包含私钥、密码、令牌、私有地址和采集截图 | 进行中 |
| SEC-003 | P0 | 高风险批准绑定具体计划 | 目标、磁盘、镜像、分区或 BIOS 选项改变后，原批准立即失效 | 待实现 |
| SEC-004 | P0 | Agent 具有最小权限 | 默认普通用户运行；需要管理员权限的单项能力单独申请 | 待实现 |
| SEC-005 | P1 | 外发数据必须可见且可控 | 上传截图或系统信息前，界面显示数据内容、目的地和用途并取得批准 | 待实现 |
| SEC-006 | P1 | 自动卸载不能扩大删除范围 | 路径越出安装根目录、缺少所有权证明或校验失败时拒绝删除 | 待实现 |
| SEC-007 | P1 | 控制失败时进入安全状态 | 连接中断、目标身份变化、状态冲突或超时后停止并释放输入 | 待实现 |

## 8. 第一版验收边界

第一版完成必须同时满足：

1. 一种真实视频输入设备连续提供可解码画面。
2. 浏览器能够显示画面和连接状态。
3. 一种 HID 后端完成无破坏性键鼠测试和全部释放。
4. 页面具有认证、单一控制者和紧急停止。
5. KVM Agent 能区分三类约定界面，并对固定 BIOS 页面提供只读建议。
6. 全过程生成不含隐私画面的结构化审计记录。

PC Agent 自动部署、自清理、系统安装和 BIOS 写入不属于第一版完成条件。
